# agent-panel · 多脑会诊面板

**中文** | [English](README.en.md)

> 把一个问题同时丢给**多个真正独立的 AI**，然后产出一份「共识 / 独有观点 / 矛盾点 / 裁判总结」的报告——而不是一个模型的单一答案。
>
> An Agent Skill that polls several independent AI "brains" in parallel (a CLI coding agent on free cloud models, one or more local OpenAI-compatible endpoints, the host model itself, plus optional human-bridged GUI apps) and aggregates their answers into a consensus / unique-findings / contradictions report. Written as a portable **Agent Skill** — no code required to use it, one optional PowerShell probe script included.

**为什么需要它**：单个模型给出的答案，你无法判断它是"想清楚了"还是"编得很顺"。
面板的价值不在于"多几个字"，而在于**把分歧写在明面上**——分歧处往往正是问题的真正难点。

---

## 1. 问题：单模型的三种失败模式

| 失败模式 | 表现 | 为什么自己发现不了 |
|---|---|---|
| **自信的错误** | 语气笃定，细节全错 | 同一模型重问三遍，它会给出同样的错误（同一个权重、同一个偏见） |
| **视角单一** | 只从自己擅长的角度回答 | 你无法知道自己"没想到的那个角度"是什么 |
| **无法自查** | 你怀疑答案有问题，但没有参照物 | 没有独立来源，你的怀疑无法被证实或证伪 |

于是有了一个自然的想法：**找个第二意见**。但手工做这件事很麻烦——你要开三个窗口、粘三次、还得自己记住谁说了什么、哪里不一致。**它会因为麻烦而不会被真正执行。**

这个技能就是把"找第二意见"从一个念头，变成一条**可靠的、有固定输出格式的操作流程**。

## 2. 核心思路

### 2.1 独立性是全部的要点

不是"同一个模型问三遍"，而是**不同基座、不同来源的模型**：

```
云端免费模型（不同厂商）  ←→  本地模型（不同基座/量化）  ←→  宿主模型（你正在用的这个）
```

⚠️ **同源成员的一致性必须降权**：两个本地模型若出自同一基座、同一量化版本，
它们的一致意见**不能算独立验证**，只能算"同一次推理的重复"。这条纪律写在技能里，
因为它是面板最容易自欺的地方——**你以为得到了三方印证，其实只是回声。**

### 2.2 固定输出格式，让分歧无处可藏

汇总一律填四栏（格式固定，避免"看起来回答了很多，其实没结论"）：

```markdown
## 会诊结果
| 成员 | 结论一句话 | 状态 |
### 🤝 共识（多数成员一致）
### 🔵 独有观点（仅一家提出 — 最有价值的部分，逐条评估可信度）
### ⚠️ 矛盾点（成员互不相同 — 给出裁判意见和理由）
### 🏁 裁判总结（综合后的最终答案）
```

### 2.3 为什么「独有观点」这一栏最值钱

共识往往是你已经知道的东西——三个模型都同意"要注意内存安全"，这句话的信息量为零。
真正改变决策的，通常是**只有一家提出、且可验证的那一条**：

> 例：某次会诊中，只有裁判提出"KV 缓存的开销取决于模型是否为混合状态层架构"。
> 这一条把争论从"开大还是开小"变成了"先确认架构类型"——**问题被重新定义了。**

所以这一栏要求**逐条标注可信度**，而不是简单罗列。

### 2.4 裁判必须是自己（而且不能只按票数）

宿主模型既当选手又当裁判，因此需要额外纪律：

- 收敛结论时**必须给出理由**，不能只数票
- **多数不等于正确**——三票里两票同错是常见情况
- 报告里必须点明"这次有几个真正独立的来源"（缺席的、同源的都要注明）

## 3. 架构

```
                    ┌──────────────────────────────┐
        问题 ──────▶│   面板主席（宿主模型）        │
                    │   1. 探测阵容  2. 并行发起    │
                    │   3. 自己作答  4. 聚合裁判    │
                    └───────┬──────────┬───────────┘
                            │          │
        ┌───────────────────┘          └────────────────────┐
        ▼                          ▼                        ▼
┌────────────────┐        ┌────────────────┐      ┌──────────────────┐
│ CLI coding     │        │ 本地端点 A/B    │      │ GUI-only 应用     │
│ agent          │        │ (OpenAI 兼容)   │      │ (人肉桥接)        │
│ 云端免费模型    │        │ 小模型 / 大模型  │      │ 用户手动复制粘贴   │
└────────────────┘        └────────────────┘      └──────────────────┘
        │                          │                        │
        └──────────────┬───────────┴────────────────────────┘
                       ▼
              ┌──────────────────┐
              │ probe: 可用性探测 │  ← scripts/panel-probe.ps1
              │ 缺席必须显式报告  │
              └──────────────────┘
```

**成员类型与适配方式**

| 类型 | 调用方式 | 适配难度 |
|---|---|---|
| 本地 OpenAI 兼容端点 | HTTP POST `/chat/completions` | 最低——几乎所有本地推理服务都提供这个接口 |
| CLI coding agent | 子进程 `run "<问题>"` | 中——需要一个能非交互执行的 CLI |
| GUI-only 应用 | **人肉桥接**（问题卡 + 粘贴回传） | 需要用户参与，但无需任何自动化 |
| 宿主模型 | 直接作答 | 零成本 |

## 4. 快速开始

```bash
# 1. 把技能放进你的宿主的 skills 目录（该格式被多个 agent 宿主兼容）
git clone https://github.com/niuyiming87-pixel/agent-panel.git ~/.dsh/skills/agent-panel   # 或只复制 SKILL.md 到你的技能目录

# 2. 复制配置并改成你机器的路径/端口/模型
cp panel.example.yml panel.yml

# 3. 开会前先探测阵容（避免"以为在线，其实全超时"）
pwsh -File scripts/panel-probe.ps1 -Config panel.yml
# 若在 Windows PowerShell 5.1 下被执行策略拦住，用：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/panel-probe.ps1 -Config panel.yml
```

然后在对话里说：

```
问面板：<你的问题>
```

示例输出见 [`examples/sample-session.md`](examples/sample-session.md)。

**探测脚本退出码**：`0` = 面板可用（≥2 名成员在线）；`1` = 只有宿主模型，不建议开会。

## 5. 设计取舍（这部分才是重点）

### 5.1 为什么默认三票，而不是全部成员？

每多一个成员，边际收益递减、成本线性上升（时间 + 算力 + 你自己的阅读成本）。
**三个独立来源**通常已经能把"共识/独有/矛盾"三栏填满；第四个成员多半只是重复前三个
里最啰嗦的那个。阵容由用户点名增减——**默认保守，能力上限不设限。**

### 5.2 为什么给本地小模型也留一个位置？

它经常"不够聪明"，但那恰恰有用：

- 它代表**另一种常见的错误模式**——把它放进矛盾点里对比，能暴露问题的概念混淆处
- 它零成本、速度快，适合当"初筛"和"机械批量活"的工人
- 它**离线**，是隐私材料的唯一去处

**用其所长，而不是要求它和大模型一样聪明。**

### 5.3 为什么声明"缺席必须报告"

**沉默的失败最贵。** 一个成员超时了，如果报告里没有它的名字，读者会默认
"所有成员都看过这个问题"——于是三票的报告被误读成五票的确定性。
这条纪律把"探测"提升为流程的一部分：先探测阵容，再开会。

### 5.4 为什么 GUI-only 应用要人肉桥接，而不是自动化驱动窗口？

自动化驱动 GUI 的方案我们评估后放弃，理由写在这里供后来者参考：

| 方案 | 为什么不采用 |
|---|---|
| 模拟点击/键盘 | 窗口坐标一变就崩，不同分辨率全废 |
| 截图 + OCR 找按钮 | 引入两级不确定性，失败时无法区分"它没回答"和"我读错了" |
| 注入/调试接口 | 依赖未公开实现，随版本更新失效，且可能违反其使用条款 |

**"让用户粘一次"的成本是 5 秒；自动化方案的成本是长期维护 + 不可靠。**
这是典型的"工程判断优先于技术炫技"：**能被稳定执行的最笨方案，胜过脆弱的聪明方案。**

### 5.5 成本路由：省的不是"钱"，是稀缺项

常见的误解是"用免费的就省钱"。实际上要按稀缺度路由：

| 任务类型 | 交给谁 | 消耗的稀缺资源 |
|---|---|---|
| 高 token 量的粗活（统计/格式化/批量转换） | 本地模型或云端免费额度 | 电费 + 时间 |
| 需要判断力的细活 | 宿主模型（最强的脑子） | 配额 / 注意力 |
| 涉及隐私的材料 | **只走本地成员** | 显存 + 时间（可接受） |

按"哪个资源最紧"路由，而不是按"哪个不花钱"一刀切。

### 5.6 隐私闸门是硬开关

问题涉及个人文件内容、未公开源码、任何密钥相关材料时：
**剔除所有云端成员，只保留本地**——而且要**主动告诉用户阵容变了**，
不能默默少一个成员（否则又回到"沉默的失败"）。

### 5.7 为什么配置只支持扁平的 `key: value`

`panel.example.yml` 刻意只解析扁平键值对（不支持嵌套/列表）。
理由：**配置的复杂度会直接变成使用摩擦**。这个技能需要改的只有
"路径、端口、模型 ID、超时、隐私开关"五项，用一个正则就能读完，
不需要引入 YAML 库、不需要依赖安装。**能用 20 行解决的，不引入 200 行。**

### 5.8 为什么单独写一个探测脚本

探测逻辑（TCP 连接 + HTTP `/health` 回退 `/v1/models` + 绕开系统代理）如果留在
技能文本里，每次开会都要模型重新推一遍、且容易推错。把它固化成脚本后：

- **确定性强**：30 秒出结果，不会因为模型"想偷懒"而跳过探测
- **可复用**：人类也能直接跑
- **暴露真实状态**：区分"离线"、"半在线（端口通但 HTTP 失败，可能仍在装载）"

## 6. 已知局限（诚实清单）

1. **面板不是投票机**。多数意见不等于正确答案；三个同源模型的一致尤其没有意义。
   它的产出是**决策素材**，不是裁决。
2. **成本翻倍**。一次会诊 ≈ 三倍的推理开销 + 你的阅读时间。事实题别用。
3. **免费模型 ID 会轮换**。示例配置里的 ID 只作占位；免费期结束后需重新拉取列表。
   这也是技能要求"模型回退链 + 报告里注明换了模型"的原因。
4. **本地小模型的知识深度有限**，专业结论要自己复核（它适合提供视角和初筛，
   不适合提供事实）。
5. **长问题传参有坑**：含引号/换行的长问题在子进程传参时容易截断，
   技能里的做法是"先写临时文件再传入"。
6. **平台差异**：探测脚本用 PowerShell 编写（已在 Windows PowerShell 5.1 与
   PowerShell 7 下验证）；Linux/macOS 需 PowerShell 7+，或自行改写为 30 行 shell。
7. **改 `.ps1` 时务必保持 UTF-8 with BOM**（本仓库踩过这个坑）：
   PowerShell 5.1 会把「无 BOM 的 UTF-8」按系统 ANSI 解析（中文 Windows 上就是 GBK），
   脚本里的中文注释与字符串立刻变乱码，并连带报出一堆莫名其妙的语法错误
   （表现为 `Unexpected token` / `The string is missing the terminator`）。
   BOM 是**刻意提交进文件本身**的（不是靠 `.gitattributes` 的 `working-tree-encoding`
   补），因为那个属性只在 `git clone` 检出时生效，而 GitHub 的 *Download ZIP* 直接发
   仓库里存的内容 —— 压缩包里会丢 BOM，下载 ZIP 的人在 PowerShell 5.1 上必然崩。
   用编辑器手改后请验证：

   ```powershell
   $b = [IO.File]::ReadAllBytes('scripts/panel-probe.ps1')[0..2]
   ($b | ForEach-Object { $_.ToString('X2') }) -join ' '   # 应为 EF BB BF
   ```

## 7. 移植到其他宿主

`SKILL.md` 采用通用 Agent Skills 结构（YAML frontmatter + Markdown 正文），
任何支持"技能/指令文件"的宿主都能加载；核心逻辑与宿主无关。

需要按宿主调整的只有三处：

1. **技能的存放目录**（各宿主不同）
2. **"宿主模型"这一票是谁**（在报告里如实称呼即可）
3. **读取截图的能力**（GUI 成员回传截图时用得到）
